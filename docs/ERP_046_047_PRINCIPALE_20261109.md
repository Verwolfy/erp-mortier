### ERP-046 — trace TVA facultative pour chaque ligne

Source : `sql/046_lignes_facture_preuve_tva_additive.sql`.

- **12 champs** ajoutés de façon additive à `public.lignes_facture` : code de règle, assiette après remise, taux, montant TVA, fait générateur, date d'effet de la règle, source/date de vérification du taux, source/justification/date de vérification/validateur de la classification.
- Contrainte `erp_lignes_facture_tva_snapshot_complet` **VALIDÉE** : soit tous les champs sont `NULL` (legacy), soit la ligne contient une preuve complète, un code reconnu NORMAL/REDUIT, des valeurs non négatives, des dates cohérentes et une TVA recalculable au centime.
- Après application, **4 factures historiques, 4 lignes**, toutes avec snapshot fiscal `NULL` ; **aucune écriture rétroactive**.
- Test direct dans `BEGIN ... ROLLBACK` sur la base principale : insertion transitoire de preuve fictive sur une ligne historique, puis tentative de modifier sa TVA de 0,01 ; la contrainte a correctement **refusé** l'incohérence. Le `ROLLBACK` a restitué **0 trace fictive, 0 snapshot rempli**.
