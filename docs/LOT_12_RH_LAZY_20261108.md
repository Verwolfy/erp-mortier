## Constat

## Correction

Le sélecteur `Vue RH` est proposé **seulement après vérification fraîche du compte, rôle RH et du droit Paie séparé via `_rh_access()`**.

| Vue | Lecture employes | Lecture demandes_conges |
|---|---|---|
| Registre employés | Oui | Non |
| Gestion congés avec droit d'écriture RH | Oui | Oui |
| Gestion congés lecture seule | Non | Oui |
| Simulation IRG (non validée) | Non | Non |
| Préparation Paie IRG/CNAS | Non | Non |
| Atelier paie fictive | Oui, sous-ensemble de test `SIM-RH` | Non |

Aucune valeur IRG/CNAS n'est changée ou qualifiée par cette optimisation. Les avertissements « simulation uniquement » et le contrôle RH / Paie à chaque déclenchement demeurent.

## Sécurité et non-régression

- Les trois vues Paie ne figurent pas dans la navigation sans droit `Paie.lecture`.
- Les formulaires d'employé/congé restent identiques ; `_rh_access()` continue à être exécuté juste avant la création pour tenir compte des droits révoqués.
- Le refus des lectures `DataReadError` / `PermissionError` reste explicite. Aucune lecture incomplète n'est transformée en liste vide.
- Les tests Streamlit AppTest historiques naviguent désormais explicitement vers les vues Congés et Atelier ; les scénarios de panne et simulation fictive restent obligatoires.
- Tests de chargements ciblés, absence d'onglets exécutés simultanément, droit Paie et blocage avant les lectures.
- Aucun SQL, modification de données Supabase, permission, transaction, fiche de paie, taux ni secret modifié.
